# Token-saving rules

1. Keep `AGENTS.md` short.
2. Keep skill descriptions precise because the initial skill catalog exposes name + description before a full skill body is loaded.
3. Put detailed factual architecture/protocol information in `docs/`, not in every skill.
4. Keep skills focused on decisions/workflows, not duplicated documentation.
5. Use specialist agents only when the task benefits from a different context.
6. Prefer targeted tests/checks before the full suite.
7. Avoid dozens of generic skills such as `python-expert`, `clean-code`, or `be-smart`.
8. If a rule is always relevant, put it in `AGENTS.md`; otherwise prefer a skill.
